# Spread the word

This website is free to copy, modify and republish. You can use it as the starting point for your own book, guide, collection of experiences or entirely different project. I would be delighted if you forked my repository and built on my experiences by adding your own. Equally, I welcome pull requests that follow the [contribution guidelines](https://mikemayne.github.io/surviving-a-psyop/#read/how_to_collaborate).

You don't need to know how to program. GitHub can host your website for free, and ChatGPT can help you customise it, write content and maintain it.

You can change absolutely everything: the title, design, chapters, advice and subject matter. You can also keep the original structure and simply replace the writing with your own.

Let ChatGPT guide you through creating, customising and publishing your own copy of this website, one step at a time.

## Step 1. Create a GitHub account

Visit [github.com](https://github.com) and create a free account.

GitHub stores your website's files, keeps a history of changes and provides the tools to publish your site.

Choose your username carefully. Your public account, contributions and website may be associated with that username.

## Step 2. Fork this website

Open the [source repository](https://github.com/mikemayne/surviving-a-psyop).

Click **Fork** in the top-right corner, then **Create fork**.

Forking creates your own copy of the entire project, including its design, chapters and website publishing instructions.

Your copy belongs to you. You can change it independently without affecting the original.

## Step 3. Connect ChatGPT

Open ChatGPT and connect your GitHub account through **Settings → Plugins**.

Give ChatGPT access to your new repository.

You can now ask it to explain the website, suggest changes, write new pages and help prepare updates. Depending on your connected tools and permissions, you may be able to have it make those changes directly.

For example, ask:

> I've forked https://github.com/mikemayne/surviving-a-psyop and want to make my own website. Please examine my repository, help me replace the original author's content and branding, update the publishing configuration for my GitHub username, and guide me through publishing it with GitHub Pages. Preserve the website's existing security safeguards where practical. Explain any changes before making them.

You can work through the project using ordinary conversation. You don't need to learn programming languages to get started.

## Step 4. Publish your website

In your forked GitHub repository, open **Settings → Pages**.

Under **Build and deployment**, select **GitHub Actions** as the source.

Open the **Actions** tab and enable workflows if GitHub asks you to. Run the existing **Build and deploy book** workflow, or commit a change to the main branch to trigger it.

You'll also need to replace the original website addresses with your own. Ask ChatGPT to update the repository's publishing configuration, sitemap, search metadata and links.

Your website will normally be available at:

`https://YOUR-USERNAME.github.io/surviving-a-psyop/`

If you rename the repository, the address changes accordingly.

## Step 5. Make it your own

Start changing things. Ask ChatGPT to help you rewrite the introduction, choose a different title, change the colours, remove chapters or create new ones.

The original project includes an interactive reader, individual text files, searchable chapter pages and a sitemap. You can reuse these features for almost any subject.

If you want to add a chapter, ChatGPT can help update the chapter file, navigation, indexes and search metadata together.

You can also ask it to review your changes for broken links, formatting problems and accessibility issues.

## Step 6. Protect your project

Your fork includes the original site's automated build and text-validation workflow files, but GitHub repository settings such as branch protection and required checks are not automatically copied.

Ask ChatGPT to help you configure pull-request reviews, required validation checks and safe publishing permissions before accepting contributions.

Consider keeping an independent backup of your repository. GitHub preserves revision history, but a separate backup provides additional protection.

Remember that a public website, repository and commit history can reveal information about you. Review the content and your account's privacy settings before publishing. A fork also retains a visible connection to the original repository.

## Step 7. Share your work

Once your website is published, you can share the address with anyone.

If you want search engines to discover it, you can submit your sitemap using Google Search Console or Bing Webmaster Tools. Indexing is not guaranteed.

You can invite contributions, accept suggestions through GitHub or simply maintain your own writing.
